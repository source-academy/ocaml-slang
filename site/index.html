OCaml for Source Academy

Source Academy runs the real OCaml toplevel (OCaml 5.5.2) in your browser: the compiler's own type checker and error messages, compiled to JavaScript with js_of_ocaml. It comes with Menhir and ocamllex, so that a lexer and a parser can be part of your program. The source is at source-academy/ocaml-slang.

Running a program and the REPL

Run runs the file that is open in the editor, in a fresh session. It shows what the program prints, and the value of the last expression (without its type):

let rec fact n = if n = 0 then 1 else n * fact (n - 1)

;; fact 5          (* shows: 120 *)

Without the ;;, fact 5 would be read as part of the definition above it. A top-level expression after a definition needs ;; (or let () = ...), exactly as in an OCaml file.

The REPL works as the ocaml toplevel does: type phrases ending in ;; and see val x : int = 3, - : int = 120 and so on, with their types. It keeps what the last run and earlier phrases defined. A run starts a new session. The phrases of one REPL entry are checked before any runs, so a syntax or type error means that none of them runs. The check stops at a directive (#warnings, #use, ...): the phrases before it run, and an error after it is found only then.

Errors come with OCaml's own message and a position in the editor. Warnings (unused variable, non-exhaustive match, ...) are shown as OCaml prints them. The toplevel directives #warnings, #rectypes, #show and #print_depth work; #require and #load do not (see below). #use reads only files in the program's own in-memory file system (for example one that the program wrote), not the files of the playground: to use another file of yours, make it a module (see programs of several files).

What is available

  • The whole OCaml language of OCaml 5.5: modules and functors, objects, GADTs, polymorphic variants, labels, ...
  • The Stdlib: List, Array, String, Hashtbl, Map, Set, Printf, Format, Buffer, Scanf, Lexing, Parsing, Bigarray, ... (Random and Sys too, with what a browser can do).
  • MenhirLib, which the parsers that Menhir generates use.
  • Menhir (version 20260209) and ocamllex: see below.

What is not available

  • Libraries outside the Stdlib and MenhirLib: Unix, Str, Thread (and so #require of any library), Dynlink. The Source Academy modules of other languages are not available either.
  • Input: read_line and reading from stdin raise End_of_file. A program cannot ask the user for input (yet).
  • Effect handlers raise Failure "Effect handlers are not supported". Domains and Mutex exist, but nothing runs in parallel.
  • Files: there is an in-memory file system for the program, not your computer's.

Programs of several files

Use the folder mode of the playground to have several files. The file that is open in the editor is the program: it is the one that runs. The other files are modules of it:

  • foo.ml (with an optional interface foo.mli) in the folder of the open file is the module Foo. A file name with a capital letter works too (Foo.ml).
  • Only the files that the program refers to are used (directly or through other modules), and they are compiled in dependency order, as module Foo : sig ... end = struct ... end. Other files are ignored, even if they have errors.
  • Modules cannot refer to each other in a cycle, and they cannot refer to the open file (Unbound module Main).
  • All files are checked before anything runs. An error in another file says which file it is in, with the line in the message; an error in the open file is also marked in the editor.
  • Files in subfolders are not found.

A module may be given as foo.ml, foo.mll or foo.mly, but not as more than one of them.

Lexers and parsers: ocamllex and Menhir

A file lexer.mll is an ocamllex lexer and becomes the module Lexer; a file parser.mly is a Menhir grammar and becomes the module Parser, with the types of its tokens. They are generated (and cached) when the program is run, with ocamllex -ml and menhir --table --explain:

(* lexer.mll *)
{ open Parser }
rule token = parse
  | [' ' '\n'] { token lexbuf }
  | ['0'-'9']+ as n { NUM (int_of_string n) }
  | '+' { PLUS } | eof { EOF }

(* parser.mly *)
%token <int> NUM
%token PLUS EOF
%left PLUS
%start <int> main
%%
main: e = expr EOF { e }
expr: n = NUM { n } | a = expr PLUS b = expr { a + b }

(* main.ml, the open file *)
let () = print_int (Parser.main Lexer.token (Lexing.from_string "1 + 2 + 3"))
  • Conflicts: Menhir's warnings about shift/reduce and reduce/reduce conflicts are shown, followed by its --explain report, which derives each conflict, so that you can see why the grammar is ambiguous (for example the dangling else). Precedence declarations (%left, %nonassoc, %prec) resolve them.
  • Errors: a syntax error in a .mll or .mly is shown with the tool's message and position. A type error in a semantic action points at the place in your .mly or .mll, not into the generated file.
  • The generated .ml and .mli files are not shown, and Menhir's options are fixed (the table back-end, because the code back-end needs more than the toplevel can offer).

Assessments and autograding

  • An OCaml question has one file: the student's program, with the question's prepend and postpend.
  • A testcase is joined to the program, run, and the last line it printed is compared with the expected answer. For an expression, that is its value as the toplevel prints it, without the type: fact 5 gives 120. Start a testcase with ;; (;; fact 5), or it is read as part of the last definition.
  • A testcase that has an error, or an uncaught exception, fails. A program that runs too long is stopped.
  • Questions with several files are not supported yet.

Limits

  • int has 32 bits (max_int = 2147483647), because the toplevel runs as JavaScript. Int64 is exact. Programs that rely on 63-bit integers (hash functions, large factorials) differ from native OCaml.
  • Deep recursion: a non-tail-recursive function can go only a few thousand calls deep (browsers differ), then Stack overflow is raised. Use tail recursion, or List.rev-based loops, for long lists.
  • The first run of a page takes a moment to load the toplevel (about 8 MB, 3.4 MB compressed); the first .mly or .mll loads Menhir (1 MB) or ocamllex (0.2 MB).
  • Behaviour that depends on the machine (Sys.word_size is 32, Sys.backend_type is Other "js_of_ocaml", time, environment) differs from native OCaml.
